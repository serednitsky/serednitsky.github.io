Notifications

A notification is an HTTP request from the system to your website. Such requests are also called callback or webhook. The system supports several types of notifications: for checking whether a payment can be processed, for informing about successful and failed payments, for notifying about changes to recurring payment subscriptions, and for informing about issued receipts.

Activation and deactivation of notifications, as well as adjustment of addresses and formats of notifications are carried out in the dashboard.
If you are using notifications to verify and change order status in your system, we recommend checking the amount, order number, and account ID of the payer.
The following rule applies to notifications (Pay, Fail, Recurrent, Cancel, Confirm, Refund): if the system cannot connect to the merchant's server, or receives an incorrect response, or a response with a code other than zero, it will make 100 attempts to deliver the message. The intervals between retries, in minutes, are as follows: 1, 2, 5, 10, 30. Response timeout: 30 seconds. In less than 1% of cases, the delay may reach 2 minutes. In other cases, it is less than a second.

Verify notifications​

All notification types (Check, Pay, Fail, Confirm, Cancel, Refund, and Recurrent) include two HTTP headers: X-Content-HMAC and Content-HMAC. These headers contain a request verification value calculated using the HMAC algorithm. The only difference between them is that the first one is generated from URL-decoded (or non-encoded) parameters, and the second one is generated from the URL-encoded parameters, which can sometimes cause processing issues. If you need to verify the authenticity and integrity of your notifications, you can calculate the verification value on your side and compare it with the value received in the request. A match confirms that the notification was sent by us and arrived in its original form.

When implementing message verification, please consider the following details:

  • For notifications sent via the POST method, the message is the request body. For GET requests, the message is the query string
  • The UTF8 encoding must be used when calculating the HMAC
  • The hash is calculated using the SHA256 function
  • The API Secret (available in the dashboard) must be used as the key
  • The calculated value is passed in base64 encoding

Examples of calculating HMAC in different programming languages.

The IP addresses from which the system sends notifications are 185.98.81.0/28, 87.251.91.160/27, 46.46.175.96/27, 46.46.168.160/27, 162.55.174.97/32, and 91.216.178.243/32.

In accordance with global security trends and identified vulnerabilities, support for the SSL 3.0 protocol has been discontinued. Support ended on June 8, 2020.

For you, this means the following:

  • If you do not use Pay, Check, Fail, Confirm, Refund, Recurrent, or Cancel notifications, no action is required.
  • If you use at least one of these notifications, you must check which HTTPS encryption protocols your server supports. If your server only supports SSL 3.0, you must upgrade it to at least TLS 1.1. Upgrading to TLS 1.3 is highly recommended. As a last resort, you can switch your notifications to the HTTP protocol.

For more details, see How to disable SSL 3.0. After June 8, HTTPS notifications to servers that support only SSL 3.0 may fail to deliver.
