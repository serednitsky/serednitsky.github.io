Token payment (recurring)

According to the NSPK requirements, merchant platforms providing telecommunication services (MCC 4814 Telecommunication Services), must provide the payer's phone number. If the phone number is missing from the request, acquiring banks will decline the transactions.



The phone number must be passed in the Phone parameter within the Payer object.


Format: digits only, without delimiters such as hyphens, or parentheses.


Example: "+71234567890"

Method for token payments using a token generated during a cryptogram payment or via a Pay notification.

A token payment can only be processed on the terminal (publicId) where the token was originally generated. If you need to share tokens across multiple terminals, send a free-form request to assistant@cp.ru.

The final status of an SBP token payment (Completed/Declined) can be obtained via the Pay and Fail notifications after the transaction has been created, rather than in the payment request response.


Endpoint: https://api.cloudpayments.ru/payments/tokens/charge for single-stage payment https://api.cloudpayments.ru/payments/tokens/auth for two-stage payment

Request parameters:

ParameterFormatRequiredDescription
AmountnumberYesThe payment amount in the transaction currency. Use a dot as the decimal separator. Number of decimal places: 2
CurrencystringNoCurrency: RUB/USD/EUR/GBP (see reference). If the parameter is omitted, the default value is RUB
AccountIdstringYesUser ID
TrInitiatorCodeintYesIndicates which party initiated the transaction.
Possible values:
0: the transaction is initiated by the merchant and based on previously stored credentials
1: the transaction is initiated by the cardholder (customer) and based on previously stored credentials
IMPORTANT! If the transaction is initiated by the merchant, you must additionally specify the PaymentScheduled parameter with a valid value in the request.
PaymentScheduledintNoThe flag of a scheduled payment based on previously stored credentials
Possible values:
0: unscheduled
1: scheduled
IMPORTANT! If this parameter is not specified in the request, the default value is 0.
TokenstringYesToken
InvoiceIdstringNoInvoice number or order number
DescriptionstringNoPayment description (free-form)
IpAddressstringNoPayer IP address
EmailstringNoPayer email for receiving payment confirmation
PayerobjectNoAdditional field used to pass payer information Use the following fields: FirstName, LastName, MiddleName, Birth, Street, Address, City, Country, Phone, Postcode
JsonDataJSONNoAny other data associated with the transaction, including instructions for creating a subscription or generating anonline receipt, must be wrapped in the cloudpayments object. We have reserved the names of the following parameters and displayed their contents in the transaction register downloaded from the CloudPayments dashboard: name, firstName, middleName, lastName, nick, phone, address, comment, birthDate

The server returns a JSON file with three components: the success field (the result of the request), the message field (a description of the error), and the model object (extended information).

Possible options​

  • Malformed request: Success: false Message: error description
  • Transaction declined: Success: false Model: transaction information and an error code
  • Transactions accepted: Success: true Model: transaction information
The request result (the Success field) does not reflect the transaction status; it only indicates the success or failure of the API request. The transaction status is reflected in the additional Status field, and can also be obtained via received notifications. For the interpretation of transaction statuses, see reference.

    "Currency":"RUB",
    "InvoiceId":"1234567",
    "Description":"Payment for goods at example.com",
    "AccountId":"user_x",
    "TrInitiatorCode": 0,
    "PaymentScheduled": 1,
    "Token":"success_1111a3e0-2428-48fb-a530-12815d90d0e8",
    "Payer":
      {

}
