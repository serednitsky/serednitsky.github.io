# Инструкция для редактора документации Cloud

Эта инструкция помогает создавать, обновлять и проверять статьи сайта CloudPayments. Редактор работает с Markdown-файлами, изображениями и несколькими настройками сайта. Программировать не нужно: достаточно уметь открывать файлы, менять текст и выполнять несколько команд.

Документация собирается из папки [`documentation`](../documentation). Русская версия хранится в `documentation/docs`, английская — в `documentation/i18n/en/docusaurus-plugin-content-docs/current`. Папка `documentation/build` содержит готовый сайт. Её не редактируют: она создаётся заново во время сборки.

## Как устроен сайт

У сайта есть два больших раздела:

- `knowledge` — база знаний для пользователей продуктов;
- `developers` — техническая документация для интеграции.

Внутри разделов материалы разложены по продуктам: `cloudpayments`, `cloudkassir` и `cloudtips`.

Основные файлы проекта:

| Что нужно изменить | Где находится |
| --- | --- |
| Русская статья | `documentation/docs/.../article-name.md` |
| Английская статья | `documentation/i18n/en/docusaurus-plugin-content-docs/current/.../article-name.md` |
| Изображение русской версии | `documentation/static/img/ru/` |
| Изображение английской версии | `documentation/static/img/en/` |
| Поисковый индекс русской версии | `documentation/static/search-index.json` |
| Поисковый индекс английской версии | `documentation/static/search-index.en.json` |
| Боковое меню | `documentation/sidebars.js` |
| Подписи меню и категорий на английском | `documentation/i18n/en/docusaurus-plugin-content-docs/current.json` и `documentation/i18n/en/docusaurus-theme-classic/navbar.json` |
| Подписи подвала на английском | `documentation/i18n/en/docusaurus-theme-classic/footer.json` |
| Тексты главной страницы | `documentation/src/pages/index.js` |
| Верхнее меню, подвал и общие настройки | `documentation/docusaurus.config.js` |

Название файла статьи пишите латиницей, в нижнем регистре, без пробелов. Используйте короткое имя по теме: `refunds-guide.md`, `payment-methods.md`. Существующие API-файлы имеют числовой префикс (`01-...md`, `02-...md`). Его не убирайте и не меняйте без согласования: он используется в исходных ссылках и порядке меню.

## Рабочий порядок

Для новой статьи используйте такой порядок:

1. Выберите раздел и папку продукта.
2. Создайте русскую статью в `documentation/docs`.
3. Добавьте английскую версию в точно такую же относительную папку.
4. Добавьте страницу в боковое меню.
5. Добавьте или обновите записи в двух поисковых индексах.
6. Подключите изображения и проверьте ссылки.
7. Соберите сайт и откройте страницы на русском и английском.

Если вы редактируете существующую страницу, начинайте с шага 6: проверьте ссылки, изображения, меню и поиск после изменения названия или расположения файла.

## Редактирование, переименование и удаление

Обычный текст статьи меняйте прямо в её Markdown-файле. Сохраняйте front matter в начале файла: если удалить разделитель `---`, поля `title` или `keywords`, страница может перестать собираться или находиться в поиске.

При переименовании файла обновите все связанные места:

1. путь в русской и английской статьях;
2. ID страницы в `documentation/sidebars.js`;
3. `url` в обоих поисковых индексах;
4. внутренние ссылки на старое имя;
5. ссылки на страницу с главной, из меню и подвала, если они есть.

Перед удалением статьи уберите её из бокового меню и обоих поисковых индексов. Проверьте, что на неё не ссылаются другие страницы. Изображение удаляйте только после проверки, что оно больше нигде не используется.

## Создание статьи

Создайте файл, например:

```text
documentation/docs/developers/cloudpayments/refunds-guide.md
```

В начале файла добавьте служебную информацию — front matter:

```md
---
title: "Как оформить возврат"
keywords:
  - "возврат"
  - "вернуть деньги"
  - "refund"
---

# Как оформить возврат

Кратко объясните, кому пригодится статья и какой результат получит читатель.

## Порядок действий

1. Выполните первый шаг.
2. Выполните второй шаг.
```

`title` — название страницы во вкладке браузера, поиске и некоторых элементах сайта. Заголовок `#` — видимый заголовок статьи. Обычно они должны совпадать. В `keywords` добавляйте название темы, синонимы, названия методов и слова, которые пользователь может ввести в поиск.

Не добавляйте в `keywords` общий список вроде «документация», «CloudPayments», «статья». Такие слова не помогают найти нужную страницу и увеличивают количество нерелевантных результатов.

Для особого публичного адреса можно добавить в front matter поле `slug`:

```md
---
title: "Как оформить возврат"
slug: "/developers/cloudpayments/refunds"
keywords:
  - "возврат"
---
```

Используйте `slug` только если адрес должен отличаться от имени файла. После изменения адреса проверьте все старые ссылки и поисковые индексы.

### Вложенный раздел

Раздел с дочерними страницами состоит из вводной страницы `index.md` и файлов статей:

```text
documentation/docs/developers/cloudpayments/guides/index.md
documentation/docs/developers/cloudpayments/guides/getting-started.md
documentation/docs/developers/cloudpayments/guides/refunds.md
```

`index.md` — страница самого раздела. В ней кратко объясните содержание и порядок материалов. Дочерние статьи перечисляются в боковом меню.

## Заголовки и структура текста

Используйте уровни заголовков по порядку:

```md
# Название статьи

## Большой раздел

### Подраздел
```

На странице должен быть один `#`. Не перескакивайте с `##` сразу на `####`. Заголовок должен описывать содержание следующего блока, а не быть просто визуально крупной надписью.

Пустая строка между абзацами, заголовками, списками и кодом обязательна. Она помогает Markdown правильно распознать структуру.

## Оформление текста

| Задача | Синтаксис | Результат |
| --- | --- | --- |
| Жирный текст | `**важно**` | **важно** |
| Курсив | `*пример*` | *пример* |
| Код в строке | ``Amount`` | `Amount` |
| Ссылка | `[текст ссылки](../path/page.md)` | Текст ссылки |
| Изображение | `![Описание](/img/ru/example.png)` | Изображение с alt-текстом |
| Перенос строки | `<br />` | Перенос внутри блока |

Списки:

```md
- Первый пункт
- Второй пункт

1. Первый шаг
2. Второй шаг
```

Внутри шага можно сделать вложенный список, добавив отступ в два или четыре пробела. Не используйте длинные абзацы внутри списков: сложное объяснение лучше вынести под список.

### Код и примеры запросов

Окружайте многострочный код тройными обратными кавычками. После первой тройки указывайте язык — так сайт правильно подсветит синтаксис:

````md
```json
{
  "Amount": 100,
  "Currency": "RUB"
}
```
````

Частые обозначения: `json`, `js`, `html`, `bash`, `shell`, `xml`. В коде сохраняйте имена API, параметров и значения enum точно так, как они должны быть скопированы пользователем. Комментарии в примерах должны объяснять действие строки, а не повторять её название.

### Таблицы

Создавайте таблицу с разделителем сразу после строки заголовков:

```md
| Параметр | Обязателен | Описание |
| --- | --- | --- |
| `Amount` | Да | Сумма платежа в рублях |
| `Currency` | Нет | Код валюты, например `RUB` |
```

В каждой строке должно быть одинаковое количество столбцов. Символ `|` внутри ячейки экранируйте как `\|`. Для короткого переноса используйте `<br />`; большую инструкцию вынесите из таблицы в обычный текст. После изменения таблицы проверьте её на узком экране.

## Изображения и другие материалы

Для русской статьи используйте изображения из `documentation/static/img/ru/`, для английской — из `documentation/static/img/en/`. Имена файлов пишите латиницей, например `refund-flow.png`.

Ссылка на изображение в русской статье:

```md
![Схема возврата платежа](/img/ru/refund-flow.png)
```

В английской статье путь должен вести в английскую папку:

```md
![Payment refund flow](/img/en/refund-flow.png)
```

В `alt` опишите смысл изображения. Если картинка декоративная, оставьте пустой alt: `![](/img/ru/decorative.png)`. Не вставляйте скриншот вместо текста, который читатель должен найти, скопировать или перевести.

Логотипы и общая иконка сайта находятся в `documentation/static/img/brands/` и `documentation/static/img/favicon.ico`. Файлы из `documentation/static/slate-pages/` — готовые демонстрационные страницы старой документации; на них ссылаются путём `/slate-pages/имя-файла.html`.

Не редактируйте файлы в `documentation/build` и не добавляйте туда изображения вручную.

## HTML и интерактивные примеры

Обычную ссылку оформляйте Markdown-синтаксисом. HTML-ссылку используйте, когда нужен атрибут, которого нет в Markdown, например открытие внешнего ресурса в новой вкладке:

```html
<a href="https://example.com" target="_blank">Внешний ресурс</a>
```

HTML-элементы `div`, `form`, `input`, `button` и `script` встречаются в интерактивных примерах API и виджетов. Оставляйте их обычным HTML только тогда, когда они должны работать на странице. Если это пример кода для копирования, заключите его в блок кода:

```html
<form action="/example" method="POST">
  <input name="Amount" value="100" />
  <button type="submit">Оплатить</button>
</form>
```

Для технической точки перехода можно использовать `id` на пустом `div`:

```html
<div id="sample-approved"></div>
```

Не меняйте существующие технические `id` без проверки всех ссылок на них. Не добавляйте JavaScript, формы и произвольные стили для оформления обычного текста.

## Ссылки внутри документации

Для перехода на другую статью используйте относительный путь к Markdown-файлу:

```md
[Общая информация](../general-information.md)
```

Для перехода к разделу добавьте ID заголовка:

```md
[Список валют](../handbook.md#список-валют)
```

Путь считается от текущего файла. Из статьи `developers/cloudpayments/` обычно используется `handbook.md`, из файла внутри `developers/cloudpayments/api/` — `../handbook.md`. Соседний API-файл указывается без `../`, например `17-sozdanie-podpiski-na-rekurrentnye-platezhi.md`.

В исходном Markdown оставляйте `.md`. Docusaurus преобразует ссылку в публичный адрес во время сборки. У API-файлов исходное имя содержит номер (`02-oplata-po-kriptogramme.md`), а публичный адрес после сборки номера не содержит.

Для ссылки внутри текущей статьи используйте `#anchor`, но сначала проверьте, что такой заголовок действительно есть. Docusaurus строит ID заголовка из его текста: `Список валют` превращается в `#список-валют`, а `Payment processing methods` — в `#payment-processing-methods`. Если одинаковый заголовок встречается несколько раз, к ID добавляется суффикс `-1`, `-2`.

При переименовании заголовка обновите все ссылки на него. При переносе статьи обновите путь во всех русских и английских файлах. Внешние ссылки с `https://` не превращайте во внутренние ссылки.

## Предупреждения и специальные блоки

Для заметок и предупреждений в проекте используются HTML-блоки:

```html
<aside class="notice">
Полезная информация для читателя.
</aside>

<aside class="warning">
Важное предупреждение о риске или ограничении.
</aside>
```

Короткий блок можно записать в одну строку:

```html
<aside class="notice">Проверяйте сумму и номер заказа до регистрации платежа.</aside>
```

Не используйте `warning` для обычного пояснения. Не вставляйте JavaScript, формы и произвольные HTML-стили без необходимости: они могут нарушить сборку или отображение на телефоне.

Встроенный демонстрационный экран добавляйте через `iframe` только для уже подготовленного файла:

```html
<iframe src="/slate-pages/demo_widget.html" width="96%" height="685px" title="Демонстрация виджета"></iframe>
```

Проверьте, что файл существует, а на мобильном экране содержимое не обрезается.

## Боковое меню

Статьи не появляются в меню автоматически. Откройте [`documentation/sidebars.js`](../documentation/sidebars.js) и добавьте ID документа в нужный массив.

Для обычного файла:

```js
const cloudPaymentsDocs = [
  'developers/cloudpayments/general-information',
  'developers/cloudpayments/refunds-guide',
];
```

ID — это путь к файлу от `documentation/docs`, без `.md`. Для файла `guides/index.md` ID будет `developers/cloudpayments/guides/index`.

Для вложенного раздела используйте категорию:

```js
{
  type: 'category',
  label: 'Руководства',
  link: {type: 'doc', id: 'developers/cloudpayments/guides/index'},
  items: [
    'developers/cloudpayments/guides/getting-started',
    'developers/cloudpayments/guides/refunds',
  ],
}
```

У API есть отдельный массив `apiItems`. В нём ID указываются без числового префикса, хотя имя файла его содержит: `02-oplata-po-kriptogramme.md` подключается как `developers/cloudpayments/api/oplata-po-kriptogramme`.

Если в категории базы знаний у продукта появляется больше одной дочерней статьи, проверьте функцию `product()` в `sidebars.js`: сейчас она принимает одну дочернюю страницу. Для нескольких страниц нужно передать массив ID и перечислить все статьи в `items`.

## Русская и английская версии

Английский файл должен иметь тот же относительный путь и то же имя:

```text
documentation/docs/developers/cloudpayments/refunds-guide.md
documentation/i18n/en/docusaurus-plugin-content-docs/current/developers/cloudpayments/refunds-guide.md
```

В английской статье переведите `title`, `keywords`, заголовки, основной текст и alt-тексты изображений. Названия API, параметры запросов, URL, значения enum и фрагменты кода оставляйте в исходном техническом виде.

Ссылки на статьи делайте относительными. Тогда русская версия будет открывать русскую страницу, а английская — английскую. Путь к файлу и ID документа должны оставаться одинаковыми в обеих локалях, но ID заголовка может отличаться после перевода. Например:

```md
[Русский заголовок](handbook.md#список-валют)
[English heading](handbook.md#list-of-currencies)
```

После перевода проверьте весь файл. Часть существующих английских страниц содержит русский текст или русские якоря. Английская локаль не исправляется автоматически при изменении русской статьи.

Названия категорий бокового меню переводятся в `documentation/i18n/en/docusaurus-plugin-content-docs/current.json`. Подписи верхнего меню переводятся в `documentation/i18n/en/docusaurus-theme-classic/navbar.json`, а подписи подвала — в `footer.json`.

## Поиск

Поиск сайта читает только два JSON-файла:

- `documentation/static/search-index.json` — русский индекс;
- `documentation/static/search-index.en.json` — английский индекс.

Поиск сопоставляет запрос с `title` и `keywords`. Текст статьи сам по себе в индекс не попадает.

Для новой или переименованной страницы добавьте запись в оба файла. Русская запись:

```json
{
  "title": "Как оформить возврат",
  "url": "/docs/developers/cloudpayments/refunds-guide",
  "keywords": ["возврат", "вернуть деньги", "refund"]
}
```

В английской записи переведите `title` и `keywords`, а `url` оставьте тем же без префикса `/en`:

```json
{
  "title": "How to issue a refund",
  "url": "/docs/developers/cloudpayments/refunds-guide",
  "keywords": ["refund", "issue a refund"]
}
```

Соблюдайте JSON-синтаксис: между объектами нужна запятая, внутри строк нельзя оставлять непарные кавычки. Для `index.md` публичный адрес обычно заканчивается `/`. Для API проверьте адрес в собранном сайте: Docusaurus убирает `.md` и числовой префикс из URL. Не копируйте адрес API из старой записи без проверки.

Скрипт [`tasks/migrate_docs.py`](migrate_docs.py) предназначен для первоначальной миграции. Не запускайте его для обычной правки: он может перезаписать статьи и поисковые индексы.

## Главная страница, меню и подвал

Тексты карточек и разделов главной страницы находятся в `documentation/src/pages/index.js`. Для новой подписи обновите блоки `ru` и `en`. Если добавляете новый пункт верхнего меню, измените `navbar.items` в `documentation/docusaurus.config.js` и его перевод в `navbar.json`.

Ссылки подвала и названия его колонок находятся в `docusaurus.config.js`; английские подписи — в `footer.json`. Для внутренних страниц используйте путь `/docs/...`, для внешних ресурсов — полный URL с `https://`.

Изменение логотипов, цветов и расположения элементов относится к общему интерфейсу сайта. Перед такой правкой проверьте соседние настройки и убедитесь, что логотип и подпись остаются доступными для пользователей экранных дикторов.

## Проверка перед публикацией

Для локального просмотра нужен Node.js 20 или новее и npm. Из папки `documentation` выполните команды. `npm install` нужен при первом запуске или после изменения зависимостей:

```bash
npm install
npm run build
npm run start
```

После `npm run start` откройте локальный адрес, который покажет Docusaurus. Проверьте новую страницу в двух вариантах:

```text
/docs/...
/en/docs/...
```

Проверьте:

- статья открывается из бокового меню;
- заголовки и уровни разделов выглядят правильно;
- все изображения загружаются и имеют понятный alt-текст;
- внутренние ссылки открывают правильную страницу и раздел;
- таблицы не распадаются на узком экране;
- код можно скопировать без лишних символов;
- английская версия действительно переведена;
- поиск находит статью по характерному слову;
- английский поиск ведёт на адрес с `/en`;
- в консоли сборки нет предупреждений о битых ссылках.

Конфигурация сейчас игнорирует предупреждения о битых якорях, поэтому якорные ссылки проверяйте вручную: откройте ссылку и убедитесь, что страница прокрутилась к нужному заголовку или блоку.

## Контрольный список перед передачей статьи

```text
[ ] Выбраны правильный раздел и продукт.
[ ] Русский файл создан или изменён в documentation/docs.
[ ] Английский файл лежит по тому же пути.
[ ] В front matter указаны title и полезные keywords.
[ ] В статье один H1, заголовки идут по порядку.
[ ] Изображения лежат в папке нужной локали и имеют alt-текст.
[ ] Внутренние ссылки используют относительные пути к .md.
[ ] Статья добавлена в sidebars.js.
[ ] Обновлены оба поисковых индекса.
[ ] Проверены русская и английская страницы.
[ ] Проверены меню, поиск, таблицы, код и мобильный вид.
[ ] npm run build завершился без ошибок.
```

## Частые ошибки

**Статья есть в папке, но её нет в меню.** Добавьте её ID в `sidebars.js`. Наличие Markdown-файла само по себе не добавляет пункт в меню.

**Ссылка открывает 404.** Проверьте путь относительно текущего файла, расширение `.md`, имя API-файла и регистр букв. В ссылке из папки `api` обычно нужен префикс `../` для перехода к статье продукта.

**Ссылка открывает страницу, но не нужный раздел.** Проверьте текст заголовка и его фактический ID в HTML собранной страницы. Для повторных заголовков ищите суффикс `-1` или `-2`.

**Статья не находится поиском.** Добавьте или исправьте запись в нужном JSON-индексе. Проверьте `title`, `keywords` и публичный `url`.

**В английской версии показывается русский текст или русская картинка.** Проверьте английский Markdown-файл и пути `/img/en/...`. Перевод и изображения для локалей хранятся отдельно.

**Сборка падает после изменения таблицы или HTML.** Проверьте закрывающие теги, количество столбцов и тройные обратные кавычки у блоков кода. Смотрите первую ошибку в выводе сборки: последующие сообщения могут быть её следствием.
