# Cryptogram payment

<aside class="notice">
According to the NSPK requirements, merchant platforms providing telecommunication services (MCC 4814 Telecommunication Services), must provide the payer's phone number. If the phone number is missing from the request, acquiring banks will decline the transactions.
<br />
<br />
The phone number must be passed in the <code>Phone</code> parameter within the <code>Payer</code> object.
<br />
Format: digits only, without delimiters such as hyphens, or parentheses.
<br />
Example: "+71234567890"
</aside>

Method to make a cryptogram payment using details generated by the encryption algorithm. To generate a cryptogram, use the [Checkout](../checkout.md) script.

**Endpoint**:
https://api.cloudpayments.ru/payments/cards/charge: for [single-stage payment](../general-information.md#payment-processing-methods)
https://api.cloudpayments.ru/payments/cards/auth: for [two-stage payment](../general-information.md#payment-processing-methods)

**Request parameters:**


Parameter | Format | Required | Description
--------- | ------- | ----------- | -----------
Amount | number | Yes | The payment amount in the transaction currency. Use a dot as the decimal separator. Number of decimal places: 2
Currency | string | No | Currency: RUB/USD/EUR/GBP (see [reference](../handbook.md#list-of-currencies)) If the parameter is omitted, the default value is RUB
IpAddress | string | Yes  |  Payer IP address
CardCryptogramPacket | string | Yes | [Card details cryptogram](../checkout.md)
Name | string | No | Cardholder name in Latin characters
PaymentUrl | string | No | Website address from which the checkout script is called
InvoiceId | string | No | Invoice number or order number
Description | string | No | Free-form payment description
CultureName | string | No |	Notification language Possible values: "ru-RU", "en-US". ([see reference](26-lokalizatsiya.md))
AccountId | string | No | Required user ID to create a subscription and obtain a token
Email | string | No | Payer email for receiving payment confirmation
Payer | object | No | Additional field used to pass payer information Use the following fields: `FirstName`, `LastName`, `MiddleName`, `Birth`, `Street`, `Address`, `City`, `Country`, `Phone`, `Postcode`
JsonData | JSON | No | Any other data associated with the transaction, including instructions for [creating a subscription](17-sozdanie-podpiski-na-rekurrentnye-platezhi.md) or generating an [online receipt](../online-kassa.md#data-transmission-format-for-online-receipts), must be wrapped in the `cloudpayments` object. We have reserved the names of the following parameters and displayed their contents in the transaction register downloaded from the CloudPayments dashboard: `name`, `firstName`, `middleName`, `lastName`, `nick`, `phone`, `address`, `comment`, `birthDate`
SaveCard | bool | No | Flag indicating whether to save the card token for payments via a stored card (see [Payment by token (recurring)](04-oplata-po-tokenu-rekarring.md)). <br />Possible values: `true`: after a successful payment, the card token will be returned, `false`: the token will not be returned (default) <br />The `SaveCard` parameter is only processed when the "Save a card token" setting is enabled in the dashboard. If the "Force Save" setting is enabled, the `SaveCard` parameter will be ignored

<aside class="notice">The <code>amount</code> parameter does not accept transaction amounts less than 0.01.</aside>

*The server returns a JSON file with the following three properties*:

* **Success field**: request result
* **Message field**: error description
* **Model object**: extended information

*Possible responses*:

* Malformed request:<br />
        **Success**: false<br />
        **Message**: error description

* Requires 3D Secure authentication:<br />
        **Success**: false<br />
	    **Model**: authentication data

* Transaction declined:<br />
        **Success**: false<br />
        **Model**: transaction information and an error code

* Transaction accepted:<br />
        **Success**: true<br />
        **Model**: transaction information

<aside class="notice">The request result (the <code>Success</code> field) does not reflect the transaction status; it only indicates the success or failure of the API request. The transaction status is reflected in the additional <code>Status</code> field, and can also be obtained via received <a href="../notifications.md">notifications</a>. For the interpretation of transaction statuses, see <a href="../handbook.md#transaction-statuses">reference</a>.</aside>
